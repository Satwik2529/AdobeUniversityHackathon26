# Scope guardrails for suggested actions

Every suggested action and every opportunity must pass all five tests before it is
written into the report.

## 1. In-scope levers only
Allowed: crawler access and robots policy, indexing, rendering and server-side output,
structured data and markup, entity identity, machine-readable content, information
architecture, retrieval-friendliness and quotability, on-site orientation and continuity,
consistency and corroboration of facts across surfaces the brand already controls, and
monitoring.

Forbidden, without exception: paid partnerships, sponsorships, influencer deals, paying an
AI vendor for placement or advertising, agency retainers, hiring, acquisitions, mergers,
and co-branding. If the main lever of a recommendation is "spend money so someone else
features us", drop it.

## 2. Mechanism test
The action must name the funnel gate it reopens and why that reopens it. An action that
cannot state its mechanism is not written.

## 3. No-guarantee test
Never claim a technique guarantees citation, ranking or inclusion in an answer. Structured
data improves entity resolution and retrieval eligibility. `llms.txt` is a low-cost
experiment with weak public evidence and no major-provider commitment to runtime use; it
is offered at low priority with that caveat attached, and its absence is never a defect.

## 4. Actionability test
State what to change, where, and how to verify it worked. Include a copy-pasteable
snippet only when a correct, site-agnostic one exists. Never invent site-specific code.

## 5. Recommend-only test
Phrase every action as advice for the site owner. Never phrase it as something the audit
did or will do. No command in the report may modify the audited site.
